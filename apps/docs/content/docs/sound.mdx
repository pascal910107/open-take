title: Sound
description: Foley from the event log — deterministic sound design for a take or a launch film, by open-foley.

A take is silent by default. Ask for sound and it is **scored from the same
event log the camera uses**: a click per click, a keystroke per typed
character, a whoosh that rides each camera move, a riser under a long typing
window, a transition breath on a navigation, and — in a launch film — a payoff
stack on the story's payoff beat.

```sh
open-take make --plan plan.json --out demos/myapp.mp4 --sound cinematic
open-take render demos/myapp.mp4 --sound minimal     # change it; re-renders
open-take render demos/myapp.mp4 --sound off
open-take launch render launch-film/launch.json --sound cinematic
```

Nothing listens to the video. The composition already knows every moment to
the millisecond, so placement is a table, not a guess, and the same take always
mixes to the same bytes. This is [open-foley](https://www.npmjs.com/package/open-foley),
published on its own — any timeline that can write an event sheet gets the
same sound design.

## Styles

| style | language |
| --- | --- |
| `cinematic` | the motion-design reference: taps and keys under whooshes, a riser into a four-layer hit (pop · impact · boom · chime) |
| `minimal` | interface sounds only — no sub, no riser; a small chime for the payoff |
| `playful` | pops for every arrival, a bright payoff |

`--sound` writes `sound: { style }` into the composition — the composition is
the source of truth, so every later render (review copy, draft, A/B reel,
master) carries the same sound. The cue sheet the render spotted lands beside
it as `foley.cues.json`: every sound, its time, level, pan and seed. Edit a
cue's `gainDb`, delete one, re-render.

## Inside a launch film

Footage inside a film is scored too: a `footage` scene or a motion `video`
layer whose recording sits beside its asset (`demo.mp4` + `demo.take/`) gets
its clicks and keystrokes at the right film time, trim and start offsets
included. Point a layer at a recording elsewhere with `take: "path/to/capture.json"`.
A `story` beat with `role: "payoff"` is the film's reveal — the one moment a
timeline cannot tell from geometry alone.

## Hearing before choosing

```sh
npx open-foley audition --out audition/
```

renders every role three ways, plus `all.wav` in order. Sound is judged by ear
the way the picture is judged by eye — A/B a style, then keep the one that
reads.

## A score you write

A [film you write yourself](/docs/cli/film) places every sound itself —
nothing is added for it. Write the score as JSON: tracks of events, each one a
drum, a tuned note, a recorded sound from the vetted palette, or a WAV of your
own; open-take renders the instruments, places the recordings, ducks one track
under another where you ask, and masters the mix.

```json
{ "version": 1, "durationS": 42.5,
  "tracks": [
    { "name": "pad", "duck": { "under": "ui", "depthDb": 4 },
      "events": [ { "at": 0, "note": "warm-pad", "pitch": ["D3", "F#3", "A3"], "dur": 4, "gainDb": -18 } ] },
    { "name": "drums", "events": [ { "at": 8, "drum": "kick-long", "gainDb": -6 } ] },
    { "name": "ui", "events": [ { "at": 18.4, "sound": "key.brown", "gainDb": -14 } ] } ] }
```

```sh
open-take sound instruments           # the drums and tuned instruments
open-take sound palette               # the recorded sounds and what each feels like
open-take sound render score.json --out score.wav
```

| event field | meaning |
| --- | --- |
| `at` | seconds |
| `drum` / `note` / `sound` / `file` | exactly one: an instrument, a palette id, or a WAV relative to the score |
| `pitch` | a note name (`"F#3"`), a MIDI number, or a list for a chord |
| `dur` | seconds (a note's length; a one-shot is cut there) |
| `gainDb` | the event's peak level, dBFS (default −12; for a `file`, a trim, default 0) |
| `pan` | −1 … 1 |
| `seed` | varies a hit, so two are never identical |

The mix is mastered to −16 LUFS under a −1.5 dBTP ceiling —
`"master": { "lufs": -14 }` to change it, `false` to keep every level as
written — and `sound render` prints each track's peak and loudness, the
balance an author who cannot listen would otherwise have to guess. The same
score always renders to the same samples.
